Written 2026-08-13. Nothing was changed in any file. This is analysis + open questions only.


================================================================
1. WHAT PROMPTED THIS
================================================================
AGENTS.md describes ZMAi relay control driven by battery SOC (>80% open the
relay and run off grid, <15% close it and go back on grid). None of that
exists in solar_monitor.py. Separately the N-PE bonding decision is keyed off
signals that cannot actually tell "on grid" from "islanded".

Intended behaviour, as stated by the owner:
  - ZMAi relay cuts the grid when battery is over 80%, and N-PE bonding
    must be ON while it is cut.
  - When the ZMAi relay is ON (grid connected), bonding must still check
    whether the system is running on battery. If on battery, N-PE is ON,
    even if the ZMAi shows ~120W. That 120W may be the inverter's own draw,
    or house load outside the inverter (e.g. house 400W, both PVs 340W).
  - N-PE mainly ON when grid consumption is very low (under ~100W) and the
    battery is supplying.

Owner clarification (2026-08-14):
  - battery installed + ZMAi wattage 50-150W: inverter is islanding
    (almost no consumption from grid), N-PE should be ON, then turn
    off ZMAi relay to go off grid.
  - battery under 15% and not charging: turn on ZMAi relay (reconnect
    to grid).
  - grid draw over 150W: N-PE OFF (real consumption, not islanding).
  - no battery (with or without PVs) + ZMAi wattage 50-150W: inverter
    cannot island, N-PE should be OFF.

    lib/python3.13/site-packages/mppsolar/protocols/pi30.py:500-523

    F = Fault         H = Power saving Y = Bypass

voltage whenever grid is PRESENT AT ITS TERMINALS, whether or not it has
transferred to battery. So the current code cannot distinguish Line mode
from Battery mode. It only detects total grid loss / relay open upstream.

QMOD == "B" is exactly the owner's "check if still runs on battery".

3. SAFETY POINT ON THE PROPOSED RULE
================================================================
"Bond when grid draw is under ~100W and the battery is supplying" bonds N-PE
while the ZMAi relay is still CLOSED. If the inverter is in Line mode at
that moment (grid-assist at low draw), its output neutral is ALREADY bonded
through the supply's N-E bond. Driving GPIO27 then creates a SECOND bond,
and neutral return current splits across the PE conductor. That is the
hazard AGENTS.md:2 exists to prevent, plus likely RCD nuisance tripping.

Owner clarification resolves this: the wattage band (50-150W) is only
meaningful WITH a battery installed - that means the inverter has islanded
and the 50-150W is house load outside the inverter, not grid draw through
it. Without a battery the inverter cannot island, so the same wattage band
is real grid consumption and bonding must stay OFF.

QMOD == "B" would be the ideal confirmation (inverter's transfer switch is
OPEN, output neutral is FLOATING), but the battery-present + wattage-band
rule is safe because without a battery the inverter physically cannot
transfer to battery mode. QMOD remains worth adding as corroboration once
validated.

4. PROPOSED DESIGN (not implemented)
================================================================
Primary (wattage-band + battery state):
    BATTERY_INSTALLED + ZMAi 50-150W  -> bond ON, then open ZMAi relay
                                         (islanding -> go off grid)
    BATTERY_INSTALLED + SOC < 15%
      + not charging                   -> close ZMAi relay (back on grid)
    ZMAi > 150W                        -> bond OFF (real grid consumption)
    NOT BATTERY_INSTALLED + any watts  -> bond OFF (cannot island)
    ZMAi relay open (off grid)         -> bond ON  regardless

Secondary (QMOD corroboration, once validated):
    QMOD == "B"            -> confirms islanding, bond ON
    QMOD == "L"            -> confirms grid, bond OFF
    QMOD == "Y" (bypass)   -> treat as L, bond OFF  - CONFIRM THIS
    QMOD == "F" (fault)    -> decide policy - CONFIRM
    QMOD unreadable        -> rely on primary wattage-band logic above

Keep from the current code (all of it is sound and worth preserving):
    - 3s stability hold before acting
    - battery reading held 30s across transient serial read failures
    - ZMAi stale 15s / inverter stale 30s windows
    - "failsafe blind" alarm + HA safety sensor when both sources are down
    - alarm throttling, systemd watchdog, MQTT re-arm on reconnect
    - reconnect inverter after 5 consecutive failed reads

Remove:
    - the grid_relay_is_open branch, or rebuild it on a signal that exists

Add (once the relay command is known):
    - islanding cutover: battery + ZMAi 50-150W -> bond N-PE, then open
      ZMAi relay (go off grid)
    - reconnect: SOC < 15% + not charging -> close ZMAi relay (back on grid)
    - interlock: bond N-PE FIRST, confirm, settle, THEN open the relay
    - grid draw > 150W -> N-PE OFF
    - keep everything gated on BATTERY_INSTALLED

Thresholds to pin down: 50 / 150W band edges, 15% SOC floor, settle
time between bonding and opening the relay.
